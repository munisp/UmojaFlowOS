# Platform-tier integrations

This record describes the data and identity integrations introduced after the original service bridge. It distinguishes **implemented client behaviour** from **deployment activation**. None of these components becomes a hidden source of payment, accounting, customer, or compliance truth: canonical operational state remains in PostgreSQL; TigerBeetle holds independently confirmed double-entry facts; and the lakehouse, OpenSearch, Redis, Sedona, and GeoLibre hold constrained projections or processing evidence.

Ambiguous roles, forged keys, and unrelated audiences are refused. |

## Data and authority boundaries

> **A successful projection or workflow call is not a settlement, customer decision, or regulator filing.** The relevant canonical PostgreSQL lifecycle procedure and, where applicable, a verified provider response remain required.

TigerBeetle’s transfer IDs are supplied by the caller and treated as end-to-end idempotency keys. The Go adapter accepts only `created` or the exact idempotent `exists` result. Any other TigerBeetle result, such as a duplicate ID with a different amount or account, is a refusal. The control plane must then reconcile the confirmed fact with the PostgreSQL projection through the Rust gateway before exposing a corresponding lifecycle change.

OpenSearch never receives monetary values, balances, account numbers, wallet addresses, document bytes, access tokens, secrets, or unapproved case fields. The lakehouse likewise rejects credential-shaped, customer, account, document, and raw-coordinate fields. Apache Sedona runs only on redacted aggregate input and only emits a cohort-suppressed aggregate map layer. GeoLibre is a viewer project generator, not an unmanaged upload or sharing endpoint.

## Deployment configuration

Every template under `infra/` is disabled by default and is mechanically validated by `scripts/infra/validate_activation_contracts.py`. Templates use secret references instead of secret values. The runtime receives resolved values only through its deployment secret mechanism; neither the browser nor configuration audit records receive a provider token, object-store key, or private identity credential.

The current sandbox can run the local Temporal, Permify, Redis, Redpanda, Dapr, Fluvio, and short-lived protocol test servers used in these regressions. It cannot host production OpenSearch, Keycloak, Apache Spark/Sedona, GeoLibre, Mojaloop, APISIX, or open-appsec; those components are complete as real activation-gated clients and deployment templates, and require a provisioned environment to perform a live product deployment check. TigerBeetle’s 1 GiB journal formatted successfully but its server did not reach a listener within the current sandbox resource envelope, so its live adapter test remains deliberately opt-in rather than reporting an unverified cluster as healthy.
