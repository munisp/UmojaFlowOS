# OpenTelemetry and Alertmanager–Novu Regulatory Evidence Mapping

## Purpose and evidence boundary

This matrix maps the UmojaFlowOS observability and notification controls to the project’s E-04 through E-09 evidence gates and the corresponding regulatory assurance control families. It is an audit preparation artifact, not a claim that live staging or CBN authorization has been completed.

> Configuration and unit-test results demonstrate control design. Only authorized staging execution logs, delivery acknowledgements, immutable hashes, and independent review demonstrate operating effectiveness.

## Evidence collection fields

Each live evidence record should include `release_sha`, `environment`, `staging_namespace`, `run_id`, `started_at`, `ended_at`, `operator_subject`, `observer_subject`, `change_record`, `command_digest`, `artifact_path`, `artifact_sha256`, `alert_fingerprint`, `trace_id`, `tenant_scope`, `redaction_check`, `cleanup_status`, and `independent_review_status`.

Tenant identifiers must be pseudonymous and scoped to the authorized test tenant. Never include customer names, account numbers, KYC documents, secrets, access tokens, private keys, or raw payment payloads in traces, alerts, screenshots, or manifests.

## Current audit conclusion

The repository currently proves control design and selected local behavior. It does not yet prove live staging operation because the local environment has only a PostgreSQL Toxiproxy proxy; Kafka and Temporal proxies, Prometheus, Alertmanager, and the Novu bridge are not active. The package therefore remains **staging-ready but regulatory NO-GO** until the missing live evidence is collected and independently signed.
