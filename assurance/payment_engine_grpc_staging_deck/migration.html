04 · Migration sequence
Migration applies in four controlled gates
Each gate must produce immutable evidence before proceeding. Any ambiguity or failure triggers an immediate stop and fail-closed posture.
Gate 01

Preflight

Discover live service accounts and verify sidecar injection status.

istioctl proxy-status
EvidenceNamespace & SA identity logs
Gate 02

Dry-run

Validate rendered YAML against cluster admission and mesh rules.

istioctl analyze -n ns
EvidenceStatic analysis & diff output
Gate 03

Canary

Apply gRPC overlay first, then policy. Route synthetic traffic only.

kubectl apply -k overlay
EvidencemTLS handshake & OTel traces
Gate 04

Rollback

Revert to HTTP 8081 if any SLO or security invariant is breached.

kubectl rollout undo
EvidenceIncident record & recovery log
Safety: Kubernetes YAML cannot create a socket; the binary must implement the listener before Gate 03.
