# Formal Disposition Register — 149 Skipped Tests

**Purpose:** Record the approved disposition of every skipped test in the control-plane full-suite run.  
**Source run:** `artifacts/control-plane-test-with-umoja-test.log`  
**Reported total:** 28 skipped files / 149 skipped tests  
**Rule:** A skip is not a pass. Missing credentials, unavailable endpoints, or unexecuted staging infrastructure must be recorded as `blocked_external_dependency` until executed or formally accepted.

## Status vocabulary

| Status | Meaning | Release effect |
|---|---|---|
| `executed_pass` | Test ran in the authorized target environment and passed with retained evidence. | Eligible for closure, subject to reviewer acceptance. |
| `executed_fail` | Test ran and failed. | NO-GO until remediated and rerun, unless an authorized exception explicitly permits continuation. |
| `blocked_external_dependency` | Test could not run because an external service, credential, endpoint, cluster, or authorization was unavailable. | Remains open; requires owner, compensating control, expiry, and approving authority. |
| `not_applicable` | Feature is explicitly outside the approved product boundary and controlled-live plan. | Requires Product/Legal/Compliance approval and evidence that no dependent control is claimed. |
| `accepted_exception` | A residual gap is knowingly accepted under a documented risk decision. | Must identify risk owner, rationale, compensating control, expiry, and approval; never permitted for prohibited P0 gaps without governing authorization. |

## Required record for every row

Each row must be completed with the exact test file/name, accountable owner, dependency, environment, evidence path and digest, pass criteria, compensating control, risk rating, decision authority, approval date, expiry/retest date, and closure status. The compensating control must be operational and testable; “will be tested later” is not a compensating control.

## Closure rules

A row can move to `executed_pass` only when the test ran in the authorized environment, the evidence is immutable and SHA-bound, the release SHA is recorded, no contradictory failure exists, and the accountable reviewer signs the row. A row can move to `not_applicable` only with a product-boundary citation and Legal/Compliance approval. A row can move to `accepted_exception` only with an explicit risk statement, compensating control, named risk owner, maximum expiry, and approval by the authority responsible for the affected gate.

No accepted exception may convert a customer-harm risk, unknown ledger outcome, WORM-integrity failure, invalid release manifest, absent CBN authorization, or missing legal/UBO evidence into a production GO decision without an explicit governing authorization that is consistent with the applicable regulatory process.
